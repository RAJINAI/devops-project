# devops-project
Version control is a fundamental process in today’s software development, and is also a crucial process in Devops. It allows the developers to track and manage changes that are made overtime. Version Control system improves teamwork, lowers development errors, and allows continuous integration and continuous delivery (CI/CD).
    One of the key concepts on the reading, Devops supports communication between development and operation teams (Kim, Humble, Debois, & Willis, 2021). Software was before developed by the developers, and the shared and deployment and maintenance were handled by the operation teams. This resulted in software malfucntions, delays and also communication issues. By supporting teamwork, automation, and regular improvement, Devops helps in improving this procedure. 
One more key lesson is the importance of version control in software development (Loeliger, Jon, McCullough, & Matthew, 2022). Developers use a version control system like Git to keep their code changes up to date, and retrieve previous versions in case of mistakes. This minimizes the chance of losing valuable work as well as enabling multiple programmers to work on the same project. 
The reading also described GitHub as being a collaborative environment where developers can upload and store their repositories online, observe code changes, and make changes to a project (Chacon & Straub, 2014). This improves teamwork and allows for sharing files quicker, keeping tracks of changed that are made and providing structed documentation.
Furthermore, DevOps contributes to quality software delivery, enabling quicker software development cycles and more reliable deployments (Forsgren, Humble, & Kim, 2018). Teams can utilize the tools, such as GitHub, to automate processes, detect problems, and update software products continually. These allows organizations to get their applications out the door faster while ensuring software quality.
Setup Process :
Figure 1: Logging into Github using an authentication token.
In Task 1, the first step was looging into GitHub through an authentication Token. An authentication token can be used to securely access Github repositories without showing passwords.
Figure 2: Creating public GitHub respository. 
The next step was to make use of the command line to create the public GitHub repository. The command “gh repo create devops-project --public” was used to create the repository, it automatically creates a repository that later can be linked with the local project files. 
Figure 3: Sucessfully created GitHub repository and is also visible online
After figure 2, the repository was also visible on the GitHub homepage. This confirms the success of the online repository and that it is ready to store project files. 
Figure 4: Using the git init command to start a local Git repository.
The Next step was to use “git init” command within the project folder to start version control locally. This command created a hidden Git directory that helped to track the folder using version control. Before adding and managing files the repository has to be initialized 
Figure 5: Making a README.md file in the Visual Studio Code editor.
Next, VS code was to build a README.md file after the initialization of repository. The README.md file includes information on how DevOps improves software delivery through teamwork, automation, and continuous integration.The README.md files are crucial as it helps the developers in understanding the projects goals and setup instruction (Spinellis, 2012). 
Figure 6: Using git status to look at the repository status.
Afterwards, the remaining step was to add and push the README.md file to the repository as per Git commands. The "git add ." command staged the changes, and the "git commit" command added them to the repository history. The importance of committing changes is that it creates a permanent mark in the system that the developers can later go back to if needed. 
Figure 7: Committing & adding files to the Git repository.
A “git push origin main” command was used to push the commits from local to the GitHub repository. This completes the sync between the local repository and the online GitHub repository.
